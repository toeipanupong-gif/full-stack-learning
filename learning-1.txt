1.3 TCP, UDP, Connection และ TLS Handshake
จากตอนก่อน เราเข้าใจแล้วว่า Browser ใช้ DNS เพื่อแปลง Domain เป็น IP Address จากนั้นขั้นต่อไปคือ “เชื่อมต่อ” ไปยัง Server
คำว่าเชื่อมต่อนี่เองที่พาเราไปเจอ TCP, UDP และ TLS
TCP คืออะไร
TCP ย่อมาจาก Transmission Control Protocol
เป็น Protocol ที่ใช้ส่งข้อมูลแบบ “เชื่อถือได้” ระหว่างเครื่องสองฝั่ง
คำว่าเชื่อถือได้ในที่นี้หมายถึง TCP จะพยายามให้ข้อมูล:
- ไปถึงปลายทาง
- ไปครบ
- ไปตามลำดับ
- ตรวจพบได้หากข้อมูลบางส่วนสูญหาย
ตัวอย่าง:
Client
  ↓
TCP Connection
  ↓
Server

Web แบบ HTTP/1.1 และ HTTP/2 ใช้ TCP เป็นพื้นฐาน
TCP ทำไมสำคัญกับ Web

Client ← ACK  ← Server

ถ้า Client ไม่ได้รับ ACK ภายในเวลาที่กำหนด อาจส่งข้อมูลเดิมใหม่
เรียกว่า:
Retransmission
Re = อีกครั้ง
Transmission = การส่งข้อมูล
ดังนั้น Retransmission = การส่งใหม่
Flow Control
Flow Control หมายถึงการควบคุมไม่ให้ฝั่งส่ง ส่งข้อมูลเร็วจนฝั่งรับรับไม่ไหว
ตัวอย่าง:
Server ส่ง 1000 MB/s

Client รับได้ 10 MB/s

ถ้าไม่มีการควบคุม Client อาจรับข้อมูลไม่ทัน
TCP จึงมีกลไกช่วยควบคุมความเร็วตามความสามารถของปลายทาง
Congestion Control
Congestion หมายถึงความแออัดของ Network
TCP จะพยายามไม่ส่งข้อมูลหนักเกินไปเมื่อ Network เริ่มแออัด
จึงต่างจากการคิดแค่ว่า:
Internet เร็ว 1 Gbps
→ ส่งเต็ม 1 Gbps ตลอด

ของจริงยังขึ้นกับหลายปัจจัย
Latency คืออะไร
Latency หมายถึงเวลาหน่วงในการส่งข้อมูลจากจุดหนึ่งไปอีกจุดหนึ่ง
เช่น:

20 ms

Bangkok → Europe
180 ms

1 second = 1000 milliseconds
Latency ต่ำหมายถึงตอบสนองเร็วกว่า
นี่เป็นเหตุผลหนึ่งที่ Cloud มักมีหลาย Region

RTT ย่อมาจาก Round-Trip Time
คือเวลาที่ข้อมูลเดินทาง:
Client
  ↓
Server
  ↓

ครบหนึ่งรอบ
ตัวอย่าง:

RTT ≈ 100 ms

TCP Handshake ต้องใช้การเดินทางหลายรอบ จึงมีผลกับ Latency
UDP คืออะไร
UDP ย่อมาจาก User Datagram Protocol
เป็นอีก Protocol หนึ่งที่อยู่ในระดับใกล้กับ TCP แต่แนวคิดต่างกัน
UDP ไม่สร้าง Connection แบบ TCP และไม่ได้รับประกันว่า:
ข้อมูลจะถึง
ข้อมูลจะครบ
ข้อมูลจะเรียงลำดับถูกต้อง

ข้อดีคือเบาและเร็วกว่าในบางสถานการณ์
TCP vs UDP
ภาพง่าย ๆ:
TCP
→ Reliable
→ Ordered
→ Connection-oriented

UDP
→ Lightweight
→ No guaranteed delivery
→ Connectionless

คำว่า Connection-oriented หมายถึงต้องสร้าง Connection ก่อน
คำว่า Connectionless หมายถึงส่งข้อมูลได้โดยไม่ต้องสร้าง Connection แบบ TCP

1.8 CSS Fundamentals — Box Model, Display, Position, Flexbox, Grid และ Responsive
CSS คือสิ่งที่ควบคุม “หน้าตาและการจัดวาง” ของ HTML

CSS Grid
Grid Layout เหมาะกับ Layout แบบ 2 มิติ
คือจัดทั้ง
Rows
Columns

ตัวอย่าง:
.container {
  display: grid;
  grid-template-columns: 1fr 1fr 1fr;
}

ได้ 3 column เท่ากัน
fr คืออะไร
fr ย่อมาจาก fraction
หมายถึงสัดส่วนของพื้นที่ที่เหลือ
เช่น:
grid-template-columns: 1fr 2fr;

column ที่สองกว้างเป็น 2 เท่าของ column แรก
repeat
เขียน:
grid-template-columns: repeat(3, 1fr);

แทน:
1fr 1fr 1fr

minmax
มีประโยชน์มากกับ Responsive Grid
grid-template-columns:
  repeat(auto-fit, minmax(250px, 1fr));

หมายถึง:
แต่ละ column
อย่างน้อย 250px
แต่ขยายได้ถึง 1fr

Browser จะจัดจำนวน column ให้ตามพื้นที่
Flexbox กับ Grid ใช้อันไหน
จำง่าย ๆ:
Flexbox
→ 1 Dimension

Grid
→ 2 Dimensions

ตัวอย่าง Navbar:
Flexbox

ตัวอย่าง Product Gallery:
Grid

Responsive Web Design คือการทำให้ UI ปรับตัวตามขนาดหน้าจอและ Context

Viewport คือพื้นที่หน้าเว็บที่ผู้ใช้มองเห็นใน Browser
เช่น Mobile อาจมีความกว้าง:

Media Query
ใช้เปลี่ยน CSS ตามเงื่อนไข

    font-size: 24px;

หมายถึงถ้าหน้าจอกว้างไม่เกิน 768px ให้ใช้ Style นี้

Breakpoint คือจุดที่ Layout เปลี่ยน
ตัวอย่าง:

768px
1024px
1280px

แต่ไม่จำเป็นต้องยึดตาม Device รุ่นใดรุ่นหนึ่ง
ควรตั้ง Breakpoint ตามจุดที่ Layout เริ่ม “พัง”
Mobile First
Mobile First คือเริ่ม Style พื้นฐานสำหรับหน้าจอเล็ก แล้วค่อยเพิ่มสำหรับจอใหญ่
เช่น:

  font-size: 24px;

  .title {

React ใช้ Function และ Closure หนักมาก
ตัวอย่าง:
useEffect(() => {
  console.log(count);
}, []);

Function ใน useEffect จะ Capture ค่า count ตาม Render ที่มันถูกสร้าง
จึงเกิดปัญหาที่เรียกว่า:

Stale หมายถึงเก่าหรือล้าสมัย
Callback อาจถือค่า State จาก Render เก่า
ตัวอย่างแนวคิด:

count = 0

React สมัยใหม่ใช้ Function Component และ Hooks เป็นหลัก ทำให้ this เจอน้อยลง
แต่ยังต้องเข้าใจเพราะ JavaScript Library และ Codebase เก่ายังมี
หลักที่ควรจำจากบทนี้
Execution Context:
บริบทที่ JavaScript ใช้ตอน Execute Code

Call Stack:
ติดตาม Function ที่กำลังทำงาน

Hoisting:
Declaration ถูกเตรียมไว้ก่อน Execution

TDZ:
Temporal Dead Zone
ช่วงที่ let/const ยังเข้าถึงไม่ได้

Closure:
Function จำ Lexical Scope ที่มันถูกสร้างได้

this:
ขึ้นกับรูปแบบการเรียก Function

Prototype:
กลไก inheritance พื้นฐานของ JavaScript

Module:
ช่วยแยก Code และ Scope
